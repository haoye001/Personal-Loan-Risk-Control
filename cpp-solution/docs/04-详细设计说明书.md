## 5. 业务逻辑详细设计

### 5.1 贷款申请状态流转

```text
+----------------+     提交申请      +----------------+
|    已提交      | ----------------> |    审核中      |
+----------------+                   +----------------+
                                     |                |
                                     | 审批通过        | 审批拒绝
                                     |                |
                                     v                v
                              +------------+    +------------+
                              |   已通过   |    |   已拒绝   |
                              +------------+    +------------+
                                     |
                                     | 生成贷款记录
                                     | 生成还款计划
                                     v
                              +------------+
                              | 还款中     |
                              +------------+
```

### 5.2 提交贷款申请流程

1. 用户登录后进入贷款产品页面；
2. 选择产品，填写金额、期限、用途；
3. 前端校验输入合法性；
4. 调用后端 `/api/loans/apply` 接口；
5. 后端调用 `/api/risk/evaluate` 获取模拟风控评分；
6. 创建贷款申请记录，状态为 `PENDING`；
7. 返回申请结果给前端。

### 5.3 审批操作流程

1. 审批人员登录 Web 管理端；
2. 进入申请列表，筛选“审核中”的申请；
3. 查看申请详情，包括用户信息、风控评分；
4. 选择“通过”或“拒绝”，填写审批意见；
5. 调用后端 `/api/approval/{id}/approve` 或 `/reject` 接口；
6. 后端更新申请状态；
7. 若审批通过，创建 loan 记录，并生成 repayment 还款计划；
8. 借款端刷新后可查看最新状态。

### 5.4 还款计划生成算法

采用 **等额本息** 方式（简化版）：

```text
月还款额 = (贷款本金 + 贷款本金 × 年利率 × 期限/12) / 期限
```

> 本阶段年利率可固定为 6%，用于演示。每期待还金额相同。

示例：
- 本金 10000 元，期限 12 个月，年利率 6%
- 总利息 = 10000 × 6% × 1 = 600 元
- 月还款额 = (10000 + 600) / 12 ≈ 883.33 元

### 6.3 网络请求封装

使用 OkHttp 封装统一请求工具类 `HttpUtil`：

```kotlin
object HttpUtil {
    private const val BASE_URL = "http://10.0.2.2:8080/api"
    private val client = OkHttpClient()

    fun post(url: String, json: String, callback: Callback) {
        val body = json.toRequestBody("application/json".toMediaType())
        val request = Request.Builder()
            .url(BASE_URL + url)
            .post(body)
            .build()
        client.newCall(request).enqueue(callback)
    }
}
```

## 8. 错误处理设计

### 8.1 后端错误码

| 错误码 | 说明 |
| :--- | :--- |
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未授权或 Token 失效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 8.2 异常处理机制

- C++ 后端使用 try-catch 统一捕获异常，返回标准错误响应。
- Android App 对网络异常进行 Toast 提示。
- Web 管理端使用 Element Plus 的 `ElMessage` 提示错误。

### 8.3 日志记录

- 后端记录请求日志、错误日志。
- 关键操作（如审批操作）记录到 operation_log 表。

## 10. 附录

### 10.1 业务流程图说明

**贷款申请业务流程**：

```text
开始 → 用户登录 → 填写申请信息 → 提交申请 → 风控评分（模拟）
 → 创建申请记录 → 返回申请结果 → 结束
```

**审批业务流程**：

```text
开始 → 审批员登录 → 查看待审批列表 → 选择申请 → 查看详情
 → 选择通过/拒绝 → 更新状态 → 生成还款计划（通过时） → 结束
```

### 10.2 接口调用时序

**提交贷款申请时序**：

```text
Android App -> C++ 后端 /api/loans/apply -> C++ 后端 /api/risk/evaluate（模拟）
 -> 写入 MySQL -> 返回结果 -> Android App
```

**审批操作时序**：

```text
Web 端 -> C++ 后端 /api/approval/{id}/approve -> 更新 MySQL
 -> 生成还款计划 -> 返回结果 -> Web 端
```

### 10.3 C++ 后端 Drogon 启动流程

```text
main.cc
  ↓
读取 config.json（数据库配置、监听端口）
  ↓
注册 Controller 路由
  ↓
初始化数据库连接池
  ↓
启动 HTTP 服务器
  ↓
监听 8080 端口
```
