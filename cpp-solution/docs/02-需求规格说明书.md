## 1. 引言

### 1.1 编写目的

本文档描述“多数据源融合的互联网个人贷款风控系统”基本版的功能需求、非功能需求、用户角色和数据需求，为系统设计、编码实现和验收测试提供依据。

### 1.2 项目范围

本阶段为基本版，范围包括：
- 安卓借款端 App：支持用户注册、登录、提交贷款申请、查询申请进度、查看还款计划。
- Web 审批管理端：支持审批人员登录、查看申请列表、审批操作、用户管理、数据统计。
- C++ 后端服务：基于 Drogon 框架提供 RESTful API，处理业务逻辑和数据持久化。
- 风控接口：本阶段仅设计接口，返回模拟评分，不实现具体风控模型。

本阶段不包含：真实支付通道、电子签章、贷后催收、复杂风控模型、多数据源接入。

### 1.3 术语定义

| 术语 | 说明 |
| :--- | :--- |
| 借款用户 | 通过 Android App 提交贷款申请的个人用户 |
| 审批人员 | 通过 Web 管理端审核贷款申请的后台用户 |
| 贷款申请 | 用户提交的借款请求，包含金额、期限、用途等信息 |
| 风控评分 | 评估用户贷款风险的分数，本阶段为模拟值 |
| 还款计划 | 贷款审批通过后生成的分期还款明细 |

## 2. 项目概述

### 2.1 系统目标

构建一个互联网个人贷款系统基本版，实现借款端在线申请、管理端在线审批、C++ 后端数据支撑的核心闭环，并为后续多数据源风控融合预留扩展接口。

### 2.2 用户角色

| 角色 | 描述 | 使用端 |
| :--- | :--- | :--- |
| 借款用户 | 需要申请个人贷款的个人 | Android App |
| 审批人员 | 审核贷款申请的工作人员 | Web 管理端 |
| 系统管理员 | 管理审批人员账号、查看系统统计 | Web 管理端 |

### 2.3 运行环境

| 端 | 运行环境 |
| :--- | :--- |
| Android 借款端 | Android 8.0 及以上系统，安装对应 App |
| Web 管理端 | Chrome、Edge、Firefox 等现代浏览器 |
| 后端服务 | C++17/20、Drogon、MySQL 8.0、Linux / Ubuntu |

## 4. 非功能需求

### 4.1 性能需求

- 后端 API 响应时间：普通查询接口不超过 1 秒。
- Android App 页面加载时间：不超过 2 秒。
- Web 管理端列表页：支持分页，单页不超过 50 条记录。
- C++ 后端可支撑并发请求，满足课程演示需求。

### 4.2 安全性需求

- 用户密码需进行加密存储（如 bcrypt）。
- 后端接口需进行身份认证，防止未授权访问。
- 敏感数据传输建议使用 HTTPS（课程演示阶段可用 HTTP）。
- 防止 SQL 注入：使用参数化查询或 ORM。

### 4.3 可用性需求

- Android App 界面简洁，操作流程不超过 3 步完成核心功能。
- Web 管理端布局清晰，审批按钮醒目。
- 系统提供友好的错误提示信息。

### 4.4 可维护性需求

- 代码结构清晰，模块职责单一。
- C++ 后端按 Controller / Service / DAO / Model / Common 分层。
- 接口文档完善，便于前后端联调。
- 使用 Git 进行版本控制，commit 信息规范。

### 4.5 兼容性需求

- Android App 兼容 Android 8.0 及以上版本。
- Web 管理端兼容主流现代浏览器。
- 后端可部署在 Linux / Ubuntu 环境。

### 5.2 数据流图说明

| 数据流 | 说明 |
| :--- | :--- |
| 用户注册 / 登录 | 用户 → App → C++ 后端 → MySQL |
| 提交贷款申请 | 用户 → App → C++ 后端 → 风控接口（模拟）→ MySQL |

## 6. 接口需求

### 6.1 接口总体说明

C++ 后端基于 Drogon 提供 RESTful API，数据格式为 JSON。主要接口组包括：

| 接口组 | 说明 |
| :--- | :--- |
| 用户接口 | 注册、登录、获取/更新用户信息 |
| 贷款产品接口 | 获取产品列表、产品详情 |
| 贷款申请接口 | 提交申请、查询申请列表、查询申请详情 |
| 审批接口 | 获取待审批列表、执行审批操作 |
| 还款接口 | 生成还款计划、查询还款计划 |
| 风控接口 | 预留接口，返回模拟评分 |
| 统计接口 | 申请量、通过率等统计 |
| 管理接口 | 管理员登录 |

### 6.2 接口安全

- 除注册、登录接口外，其他接口需携带 Token 进行身份认证。
- Token 可使用 JWT（JSON Web Token）实现。
